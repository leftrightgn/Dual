System 01 Complete Engine & Game Data Flow Architecture
Direct3D 11 & C++20

Comprehensive high-level data flow through the entire HEIN Engine and Dual combat RPG. Traces input hardware signals from Windows OS WndProc through decoupled messaging, scene graphs, actor component updates, physics separation, bone-linked hitboxes, combat damage resolution, and the Direct3D 11 rendering pipeline.

Core Engine Handle-Based Memory

Actors are owned inside a contiguous map keyed by unique ActorID (uint32_t). Components access parent and siblings via safe ID references, preventing dangling pointers during runtime entity destruction.

Messaging Decoupled Observer Bus

The Messenger singleton broadcasts message payloads to subscribed components (PlayerInputComponent, CombatStateMachineComponent) without tight coupling between input devices and actors.

Pipelines 2-Phase Physics & Collision

Physics splits movement integration (gravity, velocity) from collision resolution (Separating Axis Theorem for OBBs, Capsule segment proximity, minimum translation vector pushbacks).

System 02 Deterministic Frame Lifecycle & Tick Sequence
Game::Tick() Flow

Every frame runs through a deterministic 5-phase execution order inside Game::Tick(). This strict phase separation guarantees zero single-frame lag between animation bone matrices, hitbox positioning, physics collision detection, and GPU vertex rendering.

Phase Execution Order Table

Phase Subsystem Method Key Responsibilities
Phase A BroadCastPlayerInput & UpdateAll Evaluates AI Behaviour Trees, processes 0.2s input buffers, updates FSM states.
Phase B PhysicsSystem::UpdateMovement Integrates gravity, updates kinematic velocities, moves transform positions.
Phase C UpdateAllHierarchies & LateUpdate Cascades scene graph parent-child matrices, animates skeleton bones, locks weapon sockets.
Phase D PhysicsSystem::UpdateCollisions Tests OBB/Capsule hitboxes via SAT, resolves pushbox overlap, applies damage.
Phase E ActorManager::DrawAll & Present Renders Skybox, Water, 3D meshes, 2D UI sprites, ImGui editor, flips swapchain.

Transform Cascading Formula

For any actor $i$ with a parent $p$, the local transform is composed in SRT order (Scale, Rotation Quaternion, Translation) and multiplied by the parent world matrix:

DirectX::SimpleMath::Matrix localMatrix = DirectX::SimpleMath::Matrix::CreateScale(m_scale) * DirectX::SimpleMath::Matrix::CreateFromQuaternion(m_rotation) * DirectX::SimpleMath::Matrix::CreateTranslation(m_position); if (m_parentID != 0) { m_worldMatrix = localMatrix * parentTransform->GetWorldMatrix(); } else { m_worldMatrix = localMatrix; }

System 05 Skeletal Animation, Bone Linking & Socket Hierarchy
Joint-Accurate Hitboxes

To eliminate disconnected static hitboxes, the HEIN Engine synchronizes 3D capsule and OBB colliders directly to skeletal animation bones. BoneLinkComponent anchors colliders to single joints, while TwoBoneLinkComponent dynamically interpolates capsule orientation and height between two joints.

TwoBoneLink Math Formulation

Given two joint world coordinates $\mathbf{v}_1$ and $\mathbf{v}_2$, the capsule midpoint, orientation quaternion, and cylinder height are computed as:

DirectX::SimpleMath::Vector3 v1 = model->GetBoneWorldPosition(m_bone1); DirectX::SimpleMath::Vector3 v2 = model->GetBoneWorldPosition(m_bone2); DirectX::SimpleMath::Vector3 midPoint = (v1 + v2) * 0.5f; DirectX::SimpleMath::Vector3 dir = v2 - v1; float length = dir.Length(); dir.Normalize(); // Rotate default Up (0,1,0) vector to match joint direction DirectX::SimpleMath::Quaternion rot = DirectX::SimpleMath::Quaternion::FromToRotation( DirectX::SimpleMath::Vector3::Up, dir); m_linkedCapsule->SetPosition(midPoint); m_linkedCapsule->SetRotation(rot); m_linkedCapsule->SetHeight(length);

Socket Attachment Parenting

The weapon actor derives its transform from the wielder's socket matrix in LateUpdate:

DirectX::SimpleMath::Matrix socketWorld = socketComp->GetSocketWorldMatrix(m_socketName); DirectX::SimpleMath::Vector3 pos; DirectX::SimpleMath::Quaternion rot; DirectX::SimpleMath::Vector3 scale; socketWorld.Decompose(scale, rot, pos); weaponTransform->SetPosition(pos); weaponTransform->SetRotation(rot);

OBB SAT 15 Separating Axes

For two Orientated Bounding Boxes $A$ and $B$ with orthonormal basis vectors $\{\mathbf{u}_A^0, \mathbf{u}_A^1, \mathbf{u}_A^2\}$ and $\{\mathbf{u}_B^0, \mathbf{u}_B^1, \mathbf{u}_B^2\}$, SAT checks 15 axes:

Axes 1-3: u_A[0], u_A[1], u_A[2] (Face normals of Box A) Axes 4-6: u_B[0], u_B[1], u_B[2] (Face normals of Box B) Axes 7-15: u_A[i] x u_B[j] (9 Cross products of box edges) Projection radius r_A = sum(e_A[i] * |u_A[i] · L|) Projection radius r_B = sum(e_B[j] * |u_B[j] · L|) Separated if: |(CenterB - CenterA) · L| > (r_A + r_B)
System 07 Combat Damage Resolution & Health Subsystem
DamageSystem Pipeline

When a weapon trigger collider overlaps an enemy or player body collider, the DamageSystem performs ownership validation, invincibility status checks, block stamina mitigation, and applies damage to HealthComponent.

Damage Dealer Damage Payload

DamageDealerComponent stores damage magnitude (e.g. 25.0f physical) and damage types (Physical / Elemental). It is initialized on sword and axe actors.

Shield Defense Block Invincibility

BlockState flags HealthComponent::SetGameplayInvincible(true) while absorbing stamina. Depleted stamina triggers isBlockBroken.

Actor Queue Safe End-of-Tick Cleanup

Dead actors are placed into a pending destruction queue and cleaned up at the end of the frame, avoiding dangling pointer errors during active physics loops.

System 08 Camera Controller Subsystem & Blending Stack
Multi-Camera Architecture

The CameraController manages a stack of camera modes with smooth quaternion Slerp and position Hermite interpolation during transitions. Supports 3rd Person over-the-shoulder, 1st Person head-bone mount, Spring collision damping, Lock-on dual target tracking, and Free-fly Debug cameras.

Spring Follow Raycast Occlusion

SpringCameraMode casts a ray from player head to desired camera location. If an environment wall/mesh is hit, the camera smoothly pulls forward to prevent clipping inside walls.

Lock-On Tracking Dual Target Framing

LockOnCameraMode calculates midpoint $\mathbf{m} = \frac{\mathbf{p}_{\text{player}} + \mathbf{p}_{\text{boss}}}{2}$ and dynamically adjusts distance and pitch angle to keep both combatants in the frame.

Debug Flight 6-DOF Fly Camera

DebugCameraMode decouples from player movement, offering WASD translation, QE height control, and mouse look for inspecting scene hierarchy and collision bounds in real-time.

System 09 Environment, Terrain, Water & DirectX 11 HLSL Shaders
HLSL Rendering Pipeline

The HEIN Engine features procedural water with animated wave vertex displacement, heightmap-driven textured terrain with slope splatting and normal mapping, and cubemap skybox rendering.

Water Vertex Wave Displacement (HLSL)

// WaterVs.hlsl Wave Synthesis float wave = sin(input.position.x * uvScale + time * waveSpeed) * cos(input.position.z * uvScale + time * waveSpeed * 0.8f); output.position.y += wave * multiplier; // Normal & Fresnel in WaterPs.hlsl float3 normal1 = NormalMap.Sample(Sampler, input.tex + float2(time * 0.02, 0)).rgb * 2.0 - 1.0; float3 normal2 = NormalMap.Sample(Sampler, input.tex - float2(0, time * 0.03)).rgb * 2.0 - 1.0; float3 N = normalize(normal1 + normal2); float fresnel = pow(1.0 - saturate(dot(viewDir, N)), fresnelPower); float4 finalColor = lerp(waterColor, skyColor, fresnel) + specular;

Terrain Slope Splatting & Lighting

// Terrain_PS.hlsl float3 lightDir = -normalize(lightDirection); float diff = max(dot(normal, lightDir), 0.0f); float4 grassColor = TextureGrass.Sample(Sampler, input.tex * textureTiling); float4 rockColor = TextureRock.Sample(Sampler, input.tex * textureTiling); // Splat based on surface slope Y component float slope = 1.0f - normal.y; float4 blendColor = lerp(grassColor, rockColor, saturate(slope * 2.0f)); return blendColor * float4(diffuseColor * diff, 1.0f);
